# claw-gallery

把一个画廊站的列表页抓取到本地 SQLite，并提供一个本地网页做**同作品去重**与**语言过滤**浏览。

零第三方依赖：只用 Python 标准库（urllib / html.parser / sqlite3 / http.server），不需要 pip install、不需要 npm。

## 功能

一句话：把画廊列表页抓成本地库，按自己的规则**去重、排序、标记、下载**，并可用 API Key 关联站点账号。

### 多用户与云端同步（开发中）

- 右上角登录/退出；每个用户维护自己的站点域名、API Key、作品和批次数据。
- 本地 SQLite 默认为主数据库；登录后每用户一套独立数据库，互不串数据。
- Supabase 作为可选的云端副本，只由后端访问；“同步”执行云端拉取 → 本地合并 → 回推云端。
- 下载文件在服务器只保留一份：已有合规文件则跳过网络下载，并按当前用户标记已下载。
- 具体字段、接口、RLS 安全要求、冲突规则和验收清单见 [`需求基线.md`](需求基线.md)。

### 1. 抓取

- 前端输入任意**列表页 URL**（`/group/`、`/artist/`、`/tag/`、`/parody/`、`/character/`、`/language/`、`/search`）即可抓取
- 自动翻页、限速（默认 1.2s/页）、失败重试（429 / 5xx 指数退避、遵守 `Retry-After`）
- 出网方式可在页面顶部一键切换：**开启代理**（本机跑，走 `127.0.0.1:10808`）/ **关闭代理**（云服务器直连）
  - 开关状态会持久化到数据库，重启后自动恢复
  - 代理地址本身用 `CLAW_PROXY` 配置，默认 `http://127.0.0.1:10808`
- 可选：**详情补全**（原始标题 + 完整标签 + 页数/收藏数/上传时间）、**封面下载**到 `cover/`
- **批次号**：每次抓取生成一个批次（`#N`），记录来源 URL、时间、本批入库作品数
  - 页面顶部有**批次号下拉搜索框**，可按批次号或来源 URL 过滤，并显示「这一批是抓取哪个 URL 得到的」
- **重复数据不覆盖原始记录**：库中已存在的作品，无论从哪个 URL / 批次再抓到，都**一律跳过**：
  不更新标题/标签/页数/批次等任何字段，只刷新 `last_seen`；保留最早那次的记录与批次号
- **增量抓取**：同一 URL 已有成功批次时，从最新一页开始抓，**遇到任意已收录条目即停止翻页**
  （前置假设：上游列表按时间倒序）；可用 `CLAW_INCREMENTAL=0` 关闭
- **空批次不保留**：本次抓取新增 0 条时删除临时批次号，不留空批次
- **同 URL 只保留最新批次**：抓取成功后清理该 URL 的旧批次、把旧条目归属并入最新批次，
  「保存全部（当前批次）」始终拿到该地址的最新完整清单
- **隐藏（逻辑删除）**：卡片「隐藏」按钮；隐藏作品不展示、不下载，再次抓取到同样跳过
- **收藏同步**：收藏 tab 一键把站点账号收藏全部标记为本地「待下载」（不覆盖已有作品记录）

### 2. 同作品去重（三层策略）

| 层级 | 判定方式 | 特点 |
| --- | --- | --- |
| 1 | `gallery_id` 主键 | 重复抓取、翻页重叠不会产生重复行 |
| 2 | 详情 API **原始标题**归一化后精确匹配 | 同一作品的不同语言版本共享原始标题，零误判 |
| 3 | 列表标题**指纹**保守模糊合并 | 无详情数据时的兜底：卷号守卫 + 括号守卫 + 前缀/相似度 |

详见下文「同作品去重是怎么做的」。

### 3. 筛选与排序

- **语言过滤**：多选，chips 显示每种语言去重后的作品数
- **只看无码**：`uncensored` 标签过滤
- **只看待下载 / 只看已下载**：本地标记过滤
- **搜索**：标题、原始标题、标签、作者、社团、原作
- **排序字段**：优先级 / 最新入库 / 最旧入库 / 标题 / 作品原名称 / 版本数 / 收藏数 / 页数
- **选版优先级**（同一作品内部，决定用哪个版本代表这部作品）：
  1. **无码** > **日语** > **中文** > **英文** > 其他语言
  2. 同语言内：**页数多**优先
  3. 再同级：**新上传**优先（取详情 API 的 `upload_date`）
- **列表排序**（不同作品之间，选「优先级」排序时）：
  1. 先按 **无码 > 日语 > 中文 > 英文 > 其他** 排队
  2. 同语言内：**新作排前面**（不比页数）
- 排序规则同样作用于「我的收藏」tab

### 4. 标记与下载

- **待下载**：卡片按钮 `☆ 待下载` —— **本地队列标记**，与站点账号的真实收藏**完全分开**
- **已下载**：下载完成后在数据库标记，卡片**左上角**显示「已下载」角标
- **立即下载**（单作品）：点击后**加入服务端队列**，完成后自动从服务器保存到你的电脑
  - 队列负责取签名与下载，因此进度在所有页面可见，也不受单个请求超时影响
  - 支持两种转发模式，用 `.env` 里的 `CLAW_DOWNLOAD_MODE` 切换：
    - `cache`（推荐给磁盘充足的 VPS）：**先保存到服务器 `download/`**，再从磁盘读出发给浏览器；
      同一作品重复点击**直接命中缓存，不再请求上游**（网络中断重试也不浪费流量）
    - `stream`（默认）：**64KB 边下边转**，不在服务器落盘，适合磁盘紧张的 VPS
  - 同一作品的并发下载有锁保护，cache 模式不会重复下载；先写 `.part` 再原子改名，避免半成品被读到
  - 不能把上游的签名下载地址直接交给浏览器：签名与「取签名时出口 IP/会话」绑定，后端若走代理，浏览器直连会报 `Invalid signature`；而且跨域地址上 `download` 属性会失效、点击变成跳转
  - 因此统一下载地址为 `/api/download/file?gallery_id=..&format=..&apikey=..`（同源 + attachment）
- **服务端下载队列**：所有下载都进同一个队列（任务存数据库）
  - 并发数由 `.env` 的 `CLAW_DOWNLOAD_CONCURRENCY` 控制（默认 **5**）
  - **多个浏览器标签页看到的是同一份队列与进度**，互不影响；后端始终可见全局状态
  - 每个任务显示字节级进度（已下载 / 总大小 / 百分比），可单独取消或一键取消排队
  - 同作品 + 同格式重复入队会自动合并，不会下载两次
  - 服务重启后未完成的任务需要重新入队（API Key 只在内存里，不落库）
- **一键下载**：把全部「待下载」作品加入队列，完成后自动标记「已下载」
- **保存全部**：把**当前批次的全部作品**加入队列，保存到 `download/batch_<批次号>/`，
  同时写入 `manifest.json` 与 `works.csv` 清单（含批次来源 URL、时间、作品元数据）
- **保存位置开关**：`服务器保存` / `本地保存`
  - *服务器保存*：后端下载并落盘到项目目录，完成后标记「已下载」
  - *本地保存*：后端只返回下载地址，**浏览器循环**逐条保存到你自己的电脑
- **下载文件名**：统一为 `{作品ID}_{作品名称}.{扩展名}`，并做文件系统合规处理
  - 非法字符（尖括号、冒号、斜杠、竖线、问号、星号等）替换为空格
  - 去掉结尾的「点/空格」；避开 Windows 保留名（CON/PRN/AUX/NUL/COM1-9/LPT1-9）
  - 超长标题按可用长度截断，保证仍以作品 ID 开头；空标题退化为纯 ID
- **重新下载开关**（下载全部区域）：
  - **关闭**（默认）：先按数据库「已下载」标记跳过，避免重复下载
  - **开启**：忽略数据库标记重新下载，但**按文件名**跳过磁盘上已存在的文件（文件被删掉时会重新下）
- 下载格式支持 `zip` / `cbz` / `torrent`；批量任务有进度、可停止

### 5. 账号、站点域名与 API Key

当前阶段同时保留两种模式，最终以登录模式为主：

- **匿名兼容模式**：未登录时输入站点域名 + API Key；域名可保存到当前实例设置，Key 只暂存在浏览器 cookie，请求时通过 `X-API-Key` 传递。
- **登录模式（开发中）**：右上角注册/登录后，每个用户维护自己的站点域名与 Key；Key 只允许保存在当前用户的凭据记录中，前端和接口不返回明文。
- 两种模式都**不在首次进入时联网校验 Key**；只有真正调用需要认证的上游接口（收藏、下载）时才校验并返回可读错误。
- 上游站点地址解析顺序：**当前用户/匿名门禁设置** > `CLAW_API_ORIGIN` > 最近一次抓取的列表页 > 库内作品链接。
- 公开接口（详情、标签等）不附带 API Key；带 Key 的请求只用于需要认证的上游接口。
- **我的收藏 tab**：用当前账号的 Key 读取上游收藏列表，卡片模板与排序规则和作品库一致；“同步收藏为待下载”是显式独立操作。

### 6. 界面

- 浅色主题（白底黑字、16px 基准字号、卡片 17px 标题）
- 统一卡片网格：状态角标（已下载 / 待下载）、语言徽章、标签、变体展开列表
- 顶部：批次号下拉 + 保存位置开关；两个 tab：作品库 / 我的收藏
- 实时进度：抓取进度、详情补全、封面下载、批量下载均有进度条与滚动日志

## 快速开始

要求：Python 3.9+，本地代理已开启（例如 v2rayN / Clash 的 HTTP 代理监听 `127.0.0.1:10808`）。

```bash
cd claw-gallery
python run.py            # 默认启动 http://127.0.0.1:8787
python run.py --open     # 启动后自动打开浏览器
python run.py --seed-demo  # 无网络时写入演示数据，先预览前端
```

浏览器打开 <http://127.0.0.1:8787>，把要抓的**列表页 URL** 粘进输入框，点「开始抓取」即可。
封面会自动保存到项目 `cover/` 目录；「详情补全」「保存封面」两个开关可按需关闭以加快抓取。

## 前端技术架构

- 纯静态单页：`web/index.html` + `style.css` + 原生 JS（无框架、无打包、无 npm）
- 由 Python 内置 `ThreadingHTTPServer` 托管静态资源与 API，跨域/部署问题为零
- 前端状态集中在 `state` 对象，渲染函数（`renderGrid` / `renderLanguageBar` / `renderPager` …）为纯函数，动态文本统一 HTML 转义
- 抓取进度用 1 秒轮询 `/api/scrape/status`；缩略图 `<img>` 指向 `/api/thumb?u=…` 由后端带 Referer 转发并缓存
- 浅色主题（白底黑字、16px 基准字号）；封面优先指向 `/covers/<id>.<ext>` 本地文件，缺失时回落到远端代理

## HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/meta` | 代理、数据库路径、库统计、批次列表、上次抓取记录 |
| GET | `/api/batches` | 批次列表（批次号 / 来源 URL / 时间 / 本批作品数） |
| GET | `/api/works` | 列表查询，参数：`q`、`lang`（可重复）、`dedupe=0/1`、`uncensored=1`、`want=1`、`downloaded=1`、`site_favorites=1`、`batch=<批次号>`、`sort`（`priority`/`recent`/`oldest`/`title`/`original`/`variants`/`favorites`/`pages`）、`page`、`per_page` |
| POST | `/api/scrape` | 启动抓取，JSON：`{"url": "...", "max_pages": 0, "delay": 1.2, "enrich": true, "covers": true, "incremental": true}`（`incremental` 控制增量抓取） |
| GET | `/api/scrape/status` | 抓取进度快照（含日志） |
| POST | `/api/scrape/cancel` | 取消当前抓取（已抓数据保留） |
| GET | `/api/thumb?u=<url>` | 代理缩略图（只接受 http/https 地址，磁盘缓存） |
| GET | `/covers/<id>.<ext>` | 本地已下载封面（文件名白名单校验，防路径穿越） |
| GET | `/api/export.csv` | 按当前筛选导出 CSV（UTF-8 BOM，Excel 可直接打开） |
| POST | `/api/want-download` | 标记/取消「待下载」，JSON：`{"ids": [123], "want": true}` |
| POST | `/api/hidden` | 隐藏 / 恢复作品（逻辑删除），JSON：`{"ids": [123], "hidden": true}` |
| POST | `/api/downloaded` | 标记/取消「已下载」，JSON：`{"ids": [123], "downloaded": true}` |
| POST | `/api/download-url` | 取单个作品的下载地址（需 Key），返回给浏览器自行下载 |
| POST | `/api/download/start` | 一键下载所有「待下载」作品（需 Key，保存到 `download/`） |
| POST | `/api/batch/save` | 保存全部：把当前批次作品存到 `download/batch_<id>/` 并写清单（需 Key） |
| GET | `/api/download/status` | 批量下载进度 |
| POST | `/api/download/cancel` | 停止批量下载 |
| GET | `/api/site-favorites` | 站点账号收藏列表（需 Key），同步进本地库后按默认规则排序 |
| POST | `/api/favorites/sync` | 一键把站点收藏全部标记为本地「待下载」（需 Key） |
| GET | `/api/download/jobs` | 下载队列快照（所有任务与进度，任何标签页可见） |
| POST | `/api/download/enqueue` | 单个作品入队：`{"gallery_id": 123, "format": "zip"}` |
| POST | `/api/download/jobs/cancel` | 取消任务：`{"job_id": 1}` 或 `{"all": true}` |
| GET | `/api/download/file` | 取签名并**流式转发**作品文件给浏览器（同源 + attachment，需 Key） |
| GET | `/api/download/targets` | 批量下载的目标列表（`mode=want` 或 `mode=batch&batch_id=N`），供浏览器端循环下载 |
| POST | `/api/settings/site` | 设置站点域名，JSON：`{"origin": "example.com"}`（规范化为 `https://example.com`） |
| POST | `/api/settings/proxy` | 切换是否走代理，JSON：`{"enabled": false}`（关闭=直连） |
| POST | `/api/reset` | 清空作品与抓取记录 |

### 多用户接口（目标，开发中）

以下接口已写入需求和详细设计，但在 `功能清单.md` 第 9 节全部完成前不得视为已交付：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/auth/me` | 返回当前会话用户；未登录返回匿名状态 |
| POST | `/api/auth/register` | 注册用户并创建独立用户库 |
| POST | `/api/auth/login` | 登录、设置 `claw_session` cookie；本地无账号时可从云端回退验证 |
| POST | `/api/auth/logout` | 删除当前会话并清除 cookie |
| GET/POST | `/api/settings/credentials` | 读取设置状态 / 保存当前用户的站点域名与 API Key；永不回显完整 Key |
| GET | `/api/sync/status` | Supabase 是否配置、是否可用；未配置时不返回 500 |
| POST | `/api/sync` | 拉云端 → 合并本地 → 推回云端，并返回数量 |
| GET/POST | `/api/queue` | 当前登录用户可见的共享下载队列与进度 |

所有业务接口都应从会话解析当前用户，再把数据库路径、站点地址、API Key 和下载任务绑定到该用户；匿名模式只作为兼容回退。

## 数据库结构

`galleries`（作品条目，`gallery_id` 为主键）：

| 字段 | 说明 |
| --- | --- |
| `gallery_id` / `media_id` | 上游站点 作品 ID / 图片媒体 ID |
| `title` / `title_key` | 列表页标题 / 其指纹（模糊去重用） |
| `title_original` / `original_key` | 详情 API 原始标题（日文）/ 其归一化 key（精确去重用） |
| `title_pretty` | 展示用简洁标题（来自详情 API） |
| `num_pages` / `num_favorites` / `upload_date` / `scanlator` | 页数 / 收藏数 / 上传时间 / 汉化组（详情补全后可用） |
| `detail_fetched_at` | 详情补全时间，空表示待补全 |
| `cover_file` / `cover_fetched_at` | 本地封面文件名 / 下载时间，空表示待下载 |
| `uncensored` | 是否无码（0/1），来自详情 API 的 `uncensored` 标签 |
| `favorite` | 该版本是否被收藏（0/1）；合并卡只在推荐版本这一行展示站点收藏状态 |
| `hidden` | 逻辑删除标记（0/1）；隐藏后不展示、不下载，重抓仍跳过 |
| `want_download` | 本地「待下载」标记（0/1），与站点真实收藏分开 |
| `downloaded` / `downloaded_at` | 本地「已下载」标记及完成时间 |
| `site_favorite` | 上游账号收藏标记（0/1） |
| `url` / `thumbnail` | 作品链接 / 缩略图地址 |
| `languages` / `primary_language` | JSON 数组语言标签 / 主语言 |
| `tags` `artists` `groups` `parodies` `characters` `categories` | JSON 数组标签分类 |
| `source_url` | 抓取来源页 |
| `first_seen` / `last_seen` | 首次/最近收录时间（UTC） |

`scrape_runs`：每次抓取的记录（状态、页数、条目数、新增、重复、错误信息），前端显示「上次抓取」。

## 同作品去重是怎么做的

判断两个条目是不是同一部作品，不能只看显示标题。下面是项目离线回归中使用的虚构样本：

| 现象 | 样本例子 |
| --- | --- |
| 只有 `[English]` / `[Chinese]` 后缀不同 | Sample Vol.3 的英/中/日三个版本 |
| 中文版标题带汉化组和中文副标题 | `… Vol.3 | 示例中文副标题Vol.3` |
| 英文版标题带英文副标题 | `… Vol.2 | Sample Series Lovey-Dovey Erotic Anthology "Sample" Vol.2` |
| 前面多了展会编号 | `(C107) [SampleCircle (Various)] …` |
| 同语言重复投稿 | 两条样本 ID 不同，但标题一字不差 |
| **只差一个数字** | Sample **Vol.2** 与 **Vol.3**，字符串相似度 0.988 |

所以程序分三层，**越靠前越可信**：

### 第 1 层：gallery_id 主键（100% 可信）

上游站点 每个投稿有唯一 ID。重复抓取、翻页重叠都由主键幂等 upsert 吸收，永远不会重复。

### 第 2 层：详情 API 的原始标题精确匹配（推荐开启）

开启「详情补全」后，程序调用 `GET /api/v2/galleries/{id}` 拿到 `title.japanese`（作品原始标题）：

```
EN sample-en: [サンプルサークル (よろず)] サンプル合同「サンプル」Vol.3 (サンプルシリーズA) [英訳] [DL版]
CN sample-cn: [サンプルサークル (よろず)] サンプル合同「サンプル」Vol.3 (サンプルシリーズA) [中国翻訳] [DL版]
JP sample-jp: [サンプルサークル (よろず)] サンプル合同「サンプル」Vol.3 (サンプルシリーズA) [DL版]
```

剥离 `[英訳]` / `[中国翻訳]` / `[DL版]` 这类**语言/格式括号**后，三个版本的核心文本**完全逐字相同** → 判定为同一作品。这是精确匹配，不会有相似度误判。

离线回归中，这一层会把多语言版本合并为同一部作品，同时保持 Vol.2 / Vol.3 独立。

> 需求里提出的「先把英文和日文语义对齐，再做大量字符串匹配」在这里落成了更可靠的实现：上游详情返回的原始标题就是共同锚点，同一作品的所有翻译版本应共享同一原始标题，因此不需要真的做机器翻译。

### 第 3 层：列表标题指纹（没有详情数据时的兜底）

如果不开启详情补全，或详情请求失败，就用列表标题本身：

1. 拆成「普通文本」+「括号段」；
2. 括号段分类为**噪声**（语言名、汉化组、Digital、Incomplete、C107 场次、翻訳/版 等）或**内容**（原作名、系列名）；
3. 噪声丢掉，内容参与比对，得到"核心文本"；
4. 先按核心文本精确分组，再做保守模糊合并，且必须同时满足：
   - **卷号签名一致**（`Vol.2` 与 `Vol.3` 是不同作品，这一条专门防住 0.988 相似度的陷阱）；
   - 括号内容不冲突（一份是 `(Sample Series B)`、另一份没有，可以合并；两者括号内容不同则拒绝）；
   - 核心文本一方是另一方的前缀（≥75%），或相似度 ≥0.90 且长度比 ≥0.75；
   - 短标题（核心 <16 字符）不做模糊合并。

策略是**宁可少合并，不可误合并** —— 误合并会把两部不相干的作品永久隐藏，漏合并只是多显示一张卡片。

同一批虚构样本中，第 3 层与第 2 层的合并结果一致，并已固化为离线回归测试。

### 语言过滤

语言取自列表页卡片的 `class="gallery lang-gb"`（gb=English、jp=Japanese、cn=Chinese、kr=Korean… 共 80+ 映射），开启详情补全后会再用 API 的 `language` 标签校正。`translated` / `speechless` / `text cleaned` 这类**伪语言标签**会被忽略。

多选为"或"关系：合并卡只要包含所选语言之一即命中；语言 chips 显示的是**去重后**的作品数。
## 配置

### 配置文件 `.env`

项目根目录支持 `.env`（**已 gitignore，不会入库**），无需第三方库即可加载；
**系统环境变量优先级高于 `.env`**，所以临时覆盖可以直接用命令行环境变量。

```bash
cp .env.example .env    # 生成模板后按需修改
```

最常用的几项：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `CLAW_DOWNLOAD_MODE` | `stream` | **立即下载模式**：`cache` = 先存服务器磁盘再转发（重复下载不再请求上游）；`stream` = 64KB 流式转发不落盘 |
| `CLAW_PROXY` | `http://127.0.0.1:10808` | 出网代理；云服务器直连留空 |
| `CLAW_HOST` / `CLAW_PORT` | `127.0.0.1` / `8787` | 监听地址；部署到 VPS 改成 `0.0.0.0` 并放行端口 |
| `CLAW_DOWNLOADS_DIR` | `download/` | 一键下载输出目录；`cache` 模式也复用它作为缓存目录 |

完整清单见 `.env.example`。

## 注意事项

- 请遵守 上游站点 的使用条款与 robots 约定，本工具仅用于个人整理收藏列表；默认已限速，请勿调低间隔高频请求。
- 如果页面结构改版导致解析失败，程序会先尝试正则兼容模式；仍失败会在日志中提示「未解析到作品」。
- 列表卡片本身不含页数/收藏数等信息；勾选「详情补全」后会通过详情 API 获取，详情请求失败会自动重试。
- `--seed-demo` 写入的是样本数据（ID 9xxxxx），正式使用前可在界面点「清空数据」删除。
